# Part 9
## Questions
1. Why do we need 2 Availability Zones?
2. Why are public and private subnets separated?
3. Why does the public route table point to an Internet Gateway?
4. Why does the private app route table point to a NAT Gateway?
5. Why should the data tier usually avoid direct internet access?
6. What is the difference between a route table and a security group?
7. What is the difference between a NACL and a security group?
8. Why should SSH to private instances go through a bastion or SSM?
9. What happens if auto-assign public IP is enabled on a private subnet?
10. What happens if the data subnet gets a default route to the NAT Gateway?
## Answer
1. We need high availability in case of crushes
2. Everyone can access the public zone with an Ip. Keeping things separated increases security. This security practice is called Network Segregation, and its purpose is that only the network who needs internet connection are getting it.
3. The internet gateway is the way of a VPC to connect to the internet. That's how resources in public network like a ec2 instance can send and receive traffic from the internet.
4. The NAT Gateway can send requests and receive their response, but only that. We cant access them from outside.
5. The data tier should be the most secure and not connecting it to the internet is the best thing to do to prevent unwanted access
6. Route Tables acts as a router - directing where traffic should go
   Security Group is more like a firewall, it says what type of traffic is allowed based on protocol and ports
7. Security Group - on instances, Network ACL - on subnets
8. Private instances don't have a public ip, to access them we need a Bastion host or System Manger
9. Depends on the Route Table, if it doesn't have Internet Gateway the instance can not be accessed
10. The data subnet will gain the ability to initiate outbound connection to the internet. Security will be affected for the worst
